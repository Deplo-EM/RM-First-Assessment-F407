## 0. 先建立三张整体图

### 0.1 一张流水线总图（背下来这一张，本文就懂一半了）

```
 你写的              ①预处理            ②编译           ③汇编
 ControlTask.cpp  ────────────→  .i  ──────────→  .s  ─────────→  ControlTask.cpp.obj
 Pid.cpp          (合并/替换/筛选)     (C++→汇编)      (汇编→机器码)   Pid.cpp.obj
 main.c                                                              main.c.obj
 startup_stm32f407xx.s                                               (共 40 个 .obj)
                                                                          │
                                                     ④链接（合并 + 排地址 + 填空）
                                                                          ↓
                                                                    C_project.elf
                                                              （1 个文件，含调试信息）
                                                                          │
                                                     ⑤烧录（J-Link / Ozone 写进 Flash）
                                                                          ↓
                                                              芯片里的 0 和 1
                                                                          │
                                                     ⑥上电复位 → 启动文件 → main → 你的代码
                                                                          ↓
                                                                    电机转起来 ✓
```

**六个关卡的"工具 → 输入 → 输出"对照表**（后面每一章详细讲一个）：

| 关卡 | 工具（本次实际用的） | 输入 | 输出 | 产物体积（本次实测） |
|---|---|---|---|---|
| ① 预处理 | `arm-none-eabi-g++ -E` | `.cpp` + `.h` | `.i`（展开后的纯 C++，一般不留盘） | —— |
| ② 编译 | `arm-none-eabi-g++`（内部 cc1plus） | `.i` | `.s`（汇编，一般不留盘） | —— |
| ③ 汇编 | `arm-none-eabi-g++`（内部 as） | `.s` | **`.obj` 目标文件** | 40 个文件 |
| ④ 链接 | `arm-none-eabi-g++`（内部 ld） | 40 个 `.obj` + 链接脚本 | **`.elf`** | 1331 KB（其中真正的固件 39 KB） |
| ⑤ 烧录 | Ozone + J-Link（或 DFU） | `.elf` | 芯片 Flash 里的字节 | 39188 B（≈ 38 KB） |
| ⑥ 运行 | CPU 自己 | 上电/复位 | 电机转动 | —— |

### 0.2 五种产物的"身份证"（最容易被搞混的一组概念）

| 名字 | 中文 | 它是什么 | 谁能看懂 | 类比 |
|---|---|---|---|---|
| `.cpp` / `.h` | 源文件 | 你写的文字 | 人 ✓ | **菜谱** |
| `.obj` | 目标文件 | 一个源文件编译出来的"半成品机器码"，**地址还没定** | 链接器 ✓ | **一道做好的菜，但还没摆盘** |
| `.elf` | 可执行文件 | 所有 `.obj` 合并 + 地址排好 + 带上"说明书" | 烧录器 / 调试器 ✓ | **整桌摆好的一餐 + 菜单 + 食材清单** |
| `.bin` | 二进制镜像 | **只有字节**，没有名字、没有地址信息 | 芯片（DFU 下载）✓ | **把菜全打成泥**（能吃，但看不出是什么） |
| `.map` | 地图文件 | 链接时每个函数/变量被放在哪个地址 | 人（排查用）✓ | **仓库的货位表** |

> **为什么 `.elf` 有 1331 KB，而真正的固件只有 39 KB？**
> 因为 `.elf` 里还塞了 **调试信息**（本次实测：`.debug_info` 约 88 KB + `.debug_macro` 约 161 KB）。
> 调试信息不占芯片空间 ✓ 它只是给 Ozone 看的"说明书"：
> **哪个地址叫什么变量、是什么类型、源代码第几行** ✓ —— 这就是 Ozone 能显示 `g_wave_ref` 而不是
> `0x200004F0` 的原因 ✓

### 0.3 生活类比：开一家餐厅

| 编译阶段 | 餐厅里对应的事 |
|---|---|
| 预处理 | 把**附件**真的订进合同里（`#include`），把**简称**全替换成全称（`#define`） |
| 编译 | 把中文菜谱**翻译成厨师的方言**（汇编） |
| 汇编 | 把方言**写成标准操作卡**（机器码），但**还没写桌号** |
| 链接 | 把 40 张操作卡**装订成一本**，并**统一编好页码和桌号** |
| 烧录 | 把这本册子**交给餐厅**（芯片） |
| 上电运行 | 餐厅开门，**从第一页开始照着做** —— 于是菜（电机动作）就出来了 |

## 1. 关卡一：预处理（Preprocessing）

### 1.1 它做什么：三件事

| 动作 | 写法 | 干了什么 | 类比 |
|---|---|---|---|
| **合并** | `#include "Pid.h"` | 把那个文件的**全文复制粘贴到这一行** | 把附件**真的**订进合同 |
| **替换** | `#define BRINGUP_STAGE 2` | 之后所有 `BRINGUP_STAGE` 被**文字替换**成 `2` | 全文"查找替换" |
| **筛选** | `#if defined(USE_HAL_DRIVER)` … `#endif` | 条件成立的才留下，**不成立的整段删掉** | **门卫查证件** |

**注意三个字的区别**（很重要）：

- `#include "..."`（引号）→ 先找**你自己的目录**（`App/` 等）；
- `#include <...>`（尖括号）→ 找**系统/库目录**（`-I` 指定的那些），不找你的目录。

### 1.2 条件编译：你上次问的"板子世界 / 电脑世界"就在这一关决定

`App/ControlTask.cpp` 第 12 行：

```cpp
#if defined(USE_HAL_DRIVER)     // ================= 板子世界 =================
    ... 真正的板子代码（CAN、定时器、看门狗、串口、控制流程）...
#else                           // ================= 电脑世界 =================
    ... 四个空壳函数（名字一样，里面什么都不做）...
#endif
```

**先纠正一个常见误解**：这一行的 `//` **只注释掉"它自己这一行、从 `//` 往后"的内容** ✓
（也就是那串装饰性的"板子世界"标题）✓ **下面的代码一行都没被注释掉** ✗

`#if` 是**预处理指令**，它和 `//` 完全是两回事：

| | `// 注释` | `#if … #endif` |
|---|---|---|
| 谁处理 | 编译器（忽略它） | **预处理器**（在编译器之前） |
| 效果 | 那句话**永远不参与编译** | **看条件**：成立就留、不成立就整段删 |
| 类比 | **用笔划掉** | **门卫查通行证** |

**那"通行证"`USE_HAL_DRIVER` 从哪来？** 从命令行来 ✓（不是代码里定义的）：
`cmake/stm32cubemx/CMakeLists.txt` 第 6 行写着 `USE_HAL_DRIVER`，编译时通过 `-DUSE_HAL_DRIVER` 传给编译器 ✓

| 谁在编 | 有 `USE_HAL_DRIVER` 吗 | 预处理后剩下哪段 | 结果 |
|---|---|---|---|
| **板子固件**（你那 4 个 `.elf`） | **有** ✓ | 第 12~286 行（**真身**） | 电机真的会动 ✓ |
| **电脑判题器**（145 项测试） | **没有** ✗ | 第 287 行之后（**空壳**） | 电脑上能编过、能跑测试 ✓ |

> **为什么需要这个设计**：同一份源码，插到板子上编真身、拿到电脑上编空壳 ✓
> 好处是**算法部分（PID、角度、限幅）在电脑上就能测** ✓ 不用每次都上板子试 ✓
> —— 这就是你那 145 项测试能存在的原因 ✓
>
> **不这么做会怎样**：电脑上没有 `HAL_GPIO_WritePin` 这些板子专用函数 ✗ 链接时直接报
> `undefined reference to ...`（未定义引用）✗ 判题器就编不过了 ✗

### 1.3 本关产物

`.i` 文件（展开后的纯 C++）。本次编译**没有保留**它 ✓（CMake 不用 `-E` 那一步 ✓
编译器内部一次走完 ①②③ ✓ 所以你在 `build` 目录里看不到 `.i` 和 `.s` ✗ 这是正常的 ✓）

## 2. 关卡二：编译（Compilation）

### 2.1 它做什么

把**人能读的 C++** 变成**CPU 能执行的汇编**。中间要做四件事：

| 步骤 | 干什么 | 出错时的典型报错 |
|---|---|---|
| 词法/语法分析 | 检查"这句话合不合语法" | `expected ';' before '}'`（少分号） |
| 类型检查 | 检查"类型对不对得上" | `cannot convert 'float*' to 'uint8_t*'` |
| 优化 | 按 `-O` 等级改写代码（可能删掉"没用"的东西） | —— |
| 生成汇编 | 输出这个 CPU 认识的指令 | —— |

### 2.3 三个参数必须理解（不然以后必踩坑）

**① `-O0` 还是 `-O2`？**

| | `-O0`（本项目当前） | `-O2` |
|---|---|---|
| 代码速度 | 慢一些 | 快 |
| 代码体积 | 大 | 小 |
| **调试**（打断点、看变量） | **非常友好** ✓ | **经常"变量看不见"** ✗ |

**为什么 `-O2` 会让变量"消失"**：优化器发现某个变量算完就再没人用 → 判定"多余" → **直接删掉** ✗
于是 Ozone 里搜不到它 ✗。**这也是 `g_wave_ref/fdb/u` 必须加 `volatile` 的原因** ✓

**② `-g3` 的 `3` 是什么意思**

| 等级 | 含什么 |
|---|---|
| `-g0` | 没有调试信息 |
| `-g`（= `-g2`） | 变量名、类型、行号 |
| **`-g3`** | 上面全部 **+ 宏定义 + 头文件里的展开信息** ✓ |

**`-g3` 有一个非常好用的副作用**：它会把**编译时用过的 `-D` 宏**记进固件里 ✓
本次我就是靠这一点**证明了 4 个固件各自是哪一档** ✓（在 `.elf` 里搜到 `BRINGUP_STAGE 0 / 1 / 2` ✓）

**③ `-mfpu` / `-mfloat-abi` 是干什么的**

芯片里有一块**专门的浮点运算硬件**（FPU）✓ 这两个参数就是告诉编译器"**直接用那块硬件**" ✓
- 不写会怎样：浮点运算**改成用软件一步步模拟** ✗ → PID 计算慢好几倍 ✗ 1 kHz 控制都可能来不及 ✗

### 2.4 本关产物

`.s` 汇编文件（本项目不落盘 ✗，编译器内部直接进下一关 ✓）

## 3. 关卡三：汇编（Assembly）→ 目标文件 `.obj`

### 3.1 它做什么

把汇编**逐条翻译成机器码**（0 和 1）✓ 并按**类别**把内容装进不同的"抽屉"（**段 / section**）✓

### 3.2 目标文件里的六个"抽屉"（**这段是全文最该背的**）

| 段名 | 装什么 | 要不要占 Flash？ | 生活类比 |
|---|---|---|---|
| `.text` | **代码**（机器指令） | 占 ✓ | 说明书正文 |
| `.rodata` | **只读常量**（如字符串、常量表） | 占 ✓ | 附表 |
| `.data` | **有初值的全局/静态变量**（初值 ≠ 0） | 初值要占 ✓ | 出厂就带设置的零件 |
| `.bss` | **初值为 0（或没写初值）的全局/静态变量** | **不占** ✓（只记"有这么块地方、多大"） | 空料仓 |
| 符号表 | 名字 ↔ 地址的**通讯录** | 不占 | 花名册（**门牌号还没填**） |
| 重定位表 | "**这里缺一个地址，链接时来补**" | 不占 | 待填的空格 |
| `.debug_*` | 调试信息（变量名/类型/行号/宏） | 不占 | 说明书附录 |

**为什么 `.bss` 不占 Flash**：既然是 0，就不用真的存一堆 0 ✓
只需要记住"从地址 A 开始、长 N 字节、全填 0" ✓ —— 启动代码会替你填 ✓（见第 6 章）

### 3.3 本次实测：两个真实例子（就在今天验证过 ✓）

**例子一：`g_mode` 住在哪，说明它是"速度环固件"还是"位置环固件"**

```
stage2_speed.elf（速度环，g_mode = 0）   →  nm 输出：  200004ec  b  g_mode
stage2_pos.elf  （位置环，g_mode = 1）   →  nm 输出：  20000009  d  g_mode
                                                       ↑         ↑
                                                    地址      段的字母
```

`nm` 工具用**一个字母**告诉你变量住在哪一段 ✓：

| 字母 | 段 | 含义 |
|---|---|---|
| `t` / `T` | `.text` | 函数（小写=本文件私有，大写=公开） |
| `r` | `.rodata` | 只读常量 |
| `d` / `D` | `.data` | **有初值**的变量 |
| **`b`** / `B` | `.bss` | **初值为 0/未初始化**的变量 |

→ `g_mode = 0` 那份落在 **`b`（.bss）** ✓ 因为 0 就是"零初始化" ✓；
`g_mode = 1` 那份落在 **`d`（.data）** ✓ 因为 1 是"真的初值" ✓ ✓
**这就是"段的分类规则"在你自己代码里的活标本** ✓

**例子二：`.rodata` 里找不到 `60.0f` —— 因为它藏在"文字池"里**

我做固件校验时，先去 `.rodata`（只读常量区）搜 60.0f 的字节 `00 00 70 42` → **没搜到** ✗
后来改搜 `.text` → **搜到了** ✓

**原因（底层机制）**：ARM Cortex-M 的指令**一条只有 32 位**，塞不下一个 32 位常量 ✗
于是编译器会把常量**放在代码旁边的一个小抽屉**里（叫 **文字池 / literal pool** ✓），
指令写成 `ldr r0, [pc, #x]`（"去我后面第 x 个位置取那个数"）✓
这个文字池**物理上属于 `.text` 段** ✓ 所以常量看起来"跑进了代码区" ✓

> **记住这个结论**：在嵌入式固件里搜一个浮点常量，**不能只搜 `.rodata`** ✓ 要搜全文 ✓
> （顺带提醒：`0.5f` 这种能被指令直接编码的"好看数字"，可能连文字池都不进 ✗ 直接写进指令里 ✓）

### 3.4 为什么 `.obj` 不能直接烧进芯片

因为它**只是个半成品** ✓ 三个硬伤：

1. **地址没定**：它只知道"我这个函数叫 `PidUpdate`"，不知道要放在 Flash 的哪个门牌号 ✗
2. **引用没接**：它调用 `HAL_GPIO_WritePin`，但那个函数的机器码在**别的文件**里 ✗
3. **不是完整程序**：没有启动文件（第 6 章那个），CPU 上电根本不知道该从哪跑 ✗

**解决办法就是下一关：链接** ✓

## 4. 关卡四：链接（Linking）→ `.elf`

### 4.1 它做三件事

| 动作 | 说明 | 不做会怎样 |
|---|---|---|
| **合并** | 把 40 个 `.obj` 里同名段合到一起（所有 `.text` 拼成一个 `.text`） | 每个文件各自为政，没法烧 ✗ |
| **排地址** | 按**链接脚本**的规定，给每一段分配门牌号 | 不知道放哪 ✗ |
| **填空（重定位）** | 把"待填的空格"填上真实地址 | 调用函数时跳到错误的地址 → **跑飞 / 硬件异常** ✗ |

### 4.2 链接脚本 = 芯片的"地契"

文件：`STM32F407xx_FLASH.ld`（项目根目录）。**本次实测读出来的内容**：

```ld
MEMORY
{
  RAM    (xrw) : ORIGIN = 0x20000000, LENGTH = 128K   /* 普通内存：变量、栈 */
  CCMRAM (xrw) : ORIGIN = 0x10000000, LENGTH = 64K    /* 内核专用内存（本项目没用，占 0 字节）*/
  FLASH  (rx)  : ORIGIN = 0x08000000, LENGTH = 1024K  /* 程序存储器：掉电不丢 */
}
_estack = ORIGIN(RAM) + LENGTH(RAM);   /* 栈顶 = RAM 的最末尾 = 0x20020000 */
```

**三句话看懂**：
- **Flash**（0x08000000 起，1 MB）= **程序仓**：代码和常量住这儿，**掉电不丢** ✓
- **RAM**（0x20000000 起，128 KB）= **工作台**：变量住这儿，**掉电就没了** ✓
- **栈（stack）**：从 RAM **末尾往回长**（`_estack` = 0x20020000 = RAM 最顶端）✓ 函数调用时自动用 ✓

**为什么栈要从末尾"倒着长"**：这样"往下长的栈"和"往上长的变量区（堆）"从两头往中间走 ✓
可以用满整个 RAM 才撞上 ✓ 利用率最高 ✓

### 4.3 本次真实链接命令（逐段注释）

来自 `build/Debug/build.ninja` 第 260、262、263 行 ✓（我手工复现时用的就是这条 ✓）：

```
arm-none-eabi-g++.exe
  -mcpu=cortex-m4 -mfpu=fpv4-sp-d16 -mfloat-abi=hard   ← 和编译时一致（链接也要知道目标）
```

**`-Wl,` 是什么**：`-Wl,` 的意思是"**把后面这段原样转交给链接器**" ✓
因为 `arm-none-eabi-g++` 是"总指挥" ✓ 它自己负责编译，链接时把活转包给 `ld` ✓
`-Wl,xxx` 就是给 `ld` 的悄悄话 ✓（`-W` 是 warning 的意思但 `-Wl` 是"给 linker 的参数" ✓ 别混 ✗）

**`--gc-sections` 的好处**：STM32 的 HAL 库里**几百个函数你只用了十几个** ✗
没有它，整个 HAL 库都会被烧进去（Flash 一下子涨到几百 KB ✗）；
有了它 + 编译时的 `-ffunction-sections`（每个函数单独成段 ✓）→ 没用到的整段丢掉 ✓
（`-ffunction-sections` 和 `--gc-sections` **必须成对使用** ✓ 一个"切小块"、一个"丢小块" ✓）

## 6. 关卡六：上电之后，CPU 怎么跑到你的代码

### 6.1 上电第一瞬间发生的四件事（全部由启动文件完成）

文件：`startup_stm32f407xx.s`（项目根目录 ✓ 汇编写的 ✓）。**实测原文节选**：

```asm
    .section  .isr_vector,"a",%progbits     ; ← 这个段被链接脚本钉在 0x08000000
g_pfnVectors:
    .word  _estack                          ; ① 第 0 项：栈顶地址（0x20020000）
    .word  Reset_Handler                    ; ② 第 1 项：复位后要跳去的地方 ← CPU 就认这两项
    .word  NMI_Handler
    .word  HardFault_Handler
    ...

Reset_Handler:
    ldr   sp, =_estack                      ; ③ 把栈指针设到 RAM 末尾
    bl    SystemInit                        ; ④ 配置时钟（→ 168 MHz）
    ldr r0, =_sdata                         ; ⑤ 把 .data 段：从 Flash 拷到 RAM
    ldr r1, =_edata
    ldr r2, =_sidata
    ... 循环拷贝 ...
    ldr r2, =_sbss                          ; ⑥ 把 .bss 段：全部填 0
    ... 循环清零 ...
    bl    __libc_init_array                 ; ⑦ 调用全局对象的构造函数（C++ 需要）
    bl    main                              ; ⑧ 终于进你的 main()
```

**CPU 是怎么找到这段代码的**：ARM 芯片**硬件规定**——上电后自动去 Flash 的**第 0 个地址**
读走两个 32 位数：第一个塞进**栈指针寄存器 SP** ✓、第二个当作**入口地址跳过去** ✓
这两个数就是 `g_pfnVectors` 的头两项 ✓ 所以**向量表必须钉在 Flash 开头** ✓
（链接脚本里 `.isr_vector` 在 `0x08000000` ✓ 实测确认 ✓）

**为什么非要拷 `.data`、清 `.bss`**：
- `.data`：变量要能改 → 住 RAM ✓ 但初值掉电不能丢 → 存 Flash ✓ → 上电必须"搬一次家" ✓
- `.bss`：C/C++ 规定"没写初值的全局变量 = 0" ✓ 但没必要在 Flash 里存一堆 0 ✗ → 上电现场填 0 ✓
- **不清 `.bss` 会怎样**：那些变量里是**上电时的随机垃圾值** ✗
  比如 `g_mode` 可能变成 137 ✗ → 速度环/位置环判断直接乱套 ✗

### 6.2 进入 `main()` 之后的顺序（`Core/Src/main.c` 实测原文）

```c
int main(void)
{
  HAL_Init();              // ① HAL 库初始化：Flash 接口、SysTick（HAL 的 1 ms 时基）
  SystemClock_Config();    // ② 配时钟：外部晶振 → PLL → HCLK 168 MHz
  MX_GPIO_Init();          // ③ 以下 12 个是 CubeMX 生成的"外设初始化"
  MX_DMA_Init();
  MX_CAN1_Init();          //    CAN1（接电机，2-pin 口）
  MX_TIM6_Init();          //    TIM6（1 kHz 控制节拍）
  MX_SPI1_Init();
  MX_TIM4_Init();
  MX_USART3_UART_Init();
  MX_IWDG_Init();          //    ★ 独立看门狗：从这里开始就在"计时"了
  MX_CAN2_Init();
  MX_TIM10_Init();
  MX_USART6_UART_Init();
  MX_USART1_UART_Init();   //    4-pin 串口口就是它（PA9/PB7）

  ControlTaskInit();       // ④ 你的初始化：CAN 启动、定时器启动、PID、护栏、基准清零

  while (1)
  {
    ControlTaskLoop();     // ⑤ 主循环心跳：喂狗条件判断、护栏检查
  }
}
```

**注意两个坑**：
1. `MX_IWDG_Init()` 之后**看门狗就开始倒计时**（约 0.8 s ✓）→
   后面 `ControlTaskInit()` 里必须尽快让"喂狗条件"成立 ✓ 否则 0.8 s 后**芯片自己复位** ✗
2. 顺序是 CubeMX 排的 ✓ **不要随意调换** ✗（比如 CAN 必须在用到 CAN 的代码之前初始化 ✓）

### 6.3 1 kHz 控制节拍是怎么打到你的代码上的（实测调用链）

```
TIM6 硬件计数到 1000（1000 个 84 MHz 的计数 = 1 ms）
        │
        ▼
TIM6_DAC_IRQHandler()          ← Core/Src/stm32f4xx_it.c（CubeMX 生成的中断入口）
        │
        ▼
HAL_TIM_IRQHandler(&htim6)     ← ST 的 HAL 库：判断是"更新事件"，然后回调
        │
        ▼
HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)   ← ★ 你的代码（App/ControlTask.cpp）
        │                                                     extern "C" 避免 C++ 改名
        ▼
MainTask()                     ← 你的控制主流程：读反馈 → 算误差 → PID → 限幅 → 发 CAN
```

**为什么 TIM6 数到 1000 就是 1 ms**：TIM6 挂在 APB1 上 ✓ 定时器时钟 84 MHz ✓
预分频 84-1 后 → 计数频率 1 MHz ✓（每 1 µs 数 1 下 ✓）
自动重装值 1000-1 → 数满 1000 下 → **正好 1 ms** ✓ → 也就是 **1 kHz** ✓
（这就是面试/答辩里"控制周期多少"的标准答案 ✓）

**`extern "C"` 是干什么的**：C++ 会把函数名**改名**（name mangling ✓ 比如 `g_mode` 变成 `_ZL6g_mode` ✓）✓
而 HAL 库是 C 写的 ✓ 它按**原名字**找回调函数 ✓ → 不加 `extern "C"` 就**找不到** ✗ 链接报错 ✓

### 6.4 最后一跳：从"一个浮点数"到"电机轴上的转矩"

```
MainTask() 里算出电压给定 u（浮点，限幅在 ±3000）
        │
        ▼
SendVoltage(u)                         ← App/ControlTask.cpp
   data[idx]   = (v >> 8) & 0xFF;      ← 高字节在前（大端！官方手册第 7 页）
   data[idx+1] = v & 0xFF;
        │
        ▼
HAL_CAN_AddTxMessage(&hcan1, &txHeader, data, &mailbox)   ← 交给 ST 的 HAL
   标准帧 ID = 0x1FF（控制 1~4 号电机）
        │
        ▼
CAN1 控制器硬件 → 收发器 → CAN_H / CAN_L 两根线 → 电机驱动器
        │
        ▼
GM6020 驱动器内部：自己跑"电流环" → 控制三相电流 → 产生转矩 → 轴转
        │
        ▼
驱动器每隔 1 ms 发回反馈帧 0x205（角度 0~8191 / 转速 rpm / 转矩电流 / 温度）
        │
        ▼
CanFeedbackCallback() → 解出 angle/rpm/temp → 更新 AngleTrack / 护栏 / 图表数据
```

**一句话总结这条链**：
> **你的 C++ 算法** → 编译成 **CPU 指令** → 算出**一个整数电压值** →
> 通过 **CAN 总线**发给驱动器 → 驱动器**自己**去干"电流环"的脏活 → **电机转** ✓
> 你的固件**从不直接控制电流** ✓ 你只是每 1 ms 告诉它"我大概想要多大劲儿" ✓

## 9. 事故教学：本次真实发生的 4 件事（都是好教材）

### 9.1 旧 `.elf` 陷阱（第 5.3 节）★ 最常见

- **现象**：代码明明改了，烧进去行为没变
- **原因**：`.elf` 是 5 天前编的
- **教训**：**烧之前先看 `.elf` 的时间戳** ✓

### 9.2 光看"文件大小"判断不了固件版本

我编完 4 个固件，发现它们**大小完全一样**（都是 1334.4 KB ✗）——
因为只差几个浮点常量 ✓ 大小自然一样 ✓
**所以：判断固件对不对，要靠哈希 + 内容证据，不能靠大小** ✓

### 9.3 `.rodata` 里搜不到浮点常量 → 文字池（第 3.3 节）

- **原因**：常量被放进 `.text` 里的文字池
- **教训**：嵌入式固件里搜常量要**搜全文** ✓

### 9.4 两次编译产物不完全一样，但机器码一模一样

- **现象**：命令行带 `-DBRINGUP_STAGE=2` 编的固件比不带的长 3 KB ✗ 哈希也不同 ✗
- **验证**：我把两份的 `.text` 段逐字节对比 → **完全一致** ✓
- **原因**：差别**只在调试信息**里（`-g3` 会记录"这次编译用了哪些 `-D` 宏" ✓）
- **结论**：**功能完全相同** ✓ 差的是"日志" ✓
- **附带好处**：正因为宏被记进了固件，我才能证明 4 个固件各自是哪一档 ✓

## 10. 复习速查表（考前只看这一章）

### 10.1 六个关卡一句话

| 关卡 | 一句话 | 产物 |
|---|---|---|
| ① 预处理 | 合并头文件、替换宏、按条件删代码 | `.i` |
| ② 编译 | C++ → 汇编（查语法、查类型、优化） | `.s` |
| ③ 汇编 | 汇编 → 机器码，按段分类装箱 | `.obj` |
| ④ 链接 | 合并 40 个 `.obj`、排地址、填空 | `.elf` + `.map` |
| ⑤ 烧录 | 把段写进 Flash（调试信息不烧） | 芯片里的 39188 B |
| ⑥ 运行 | 向量表 → 启动文件 → `main` → 你的代码 | 电机转 |

### 10.2 段的速查（`nm` 字母 + 三个"要不要占 Flash"）

| 段 | 装什么 | 占 Flash？ | `nm` 字母 | 初始化时机 |
|---|---|---|---|---|
| `.text` | 代码 | 占 ✓ | `t/T` | —— |
| `.rodata` | 只读常量 | 占 ✓ | `r` | —— |
| `.data` | 有初值的全局变量 | 初值占 ✓ | `d/D` | **启动时从 Flash 拷到 RAM** |
| `.bss` | 初值为 0 的全局变量 | **不占** ✓ | `b/B` | **启动时清零** |
| `.isr_vector` | 中断向量表 | 占 ✓ | —— | 必须是 Flash 第 0 字节 |
| 栈/堆 | 函数调用的工作区 | 不占 | —— | 运行时用 |

### 10.4 编译参数速查（最该记住的 6 个）

| 参数 | 作用 | 去掉/改了会怎样 |
|---|---|---|
| `-mcpu=cortex-m4` | 目标内核 | 生成错误指令集 ✗ |
| `-mfpu=fpv4-sp-d16 -mfloat-abi=hard` | 用硬件浮点 | 浮点改用软件模拟 → **慢好几倍** ✗ |
| `-O0` | 不优化（好调试） | 改 `-O2` → 变量可能被优化掉 → 调试看不见 ✗ |
| `-g3` | 最详细调试信息（含宏） | 去掉 → Ozone 只看到地址，没有名字 ✗ |
| `-Wall` | 所有警告 | 去掉 → 隐患不报警 ✗ |
| `-fdata-sections -ffunction-sections` + `-Wl,--gc-sections` | 切小块 + 丢没用的 | 固件从 39 KB 涨到几百 KB ✗ |
