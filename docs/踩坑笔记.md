# 一、A 阶段（工具链与环境）

## A1. 点了 `Save Project As`，CubeMX 警告要删掉整个工程目录

**现象**：弹窗说 `ALL Files and Directories in D:\ForTest\C_project will be deleted`，接着报 `拒绝访问`。

**原因**：两个错叠在一起。
1. 该点 **`File → Open Project`**（打开已有工程），不是 `Save Project As`（另存为新工程）；
2. 老师给的附件被我 `Copy-Item` 复制时**把"只读"属性一起带过来了**，CubeMX 想写 `.ioc` 就被系统拒绝。

**正确做法**：
- 打开工程一律用 `File → Open Project`，看到"删除整个目录"的弹窗**一律点取消**；
- 附件/压缩包里出来的文件常带只读属性，批量清掉：
  ```powershell
  Get-ChildItem 'D:\ForTest\C_project' -Recurse -File | ForEach-Object { $_.IsReadOnly = $false }
  ```

**记住一句话**：**"另存为"和"打开"是完全不同的两件事**；文件只读会让工具报出看起来毫不相关的错。

## A2. `Could not find toolchain file: "cmake/arm-none-eabi"`

**现象**：`CMake Error ... Could not find toolchain file` 外加一句 `CMake Warning: Ignoring extra path from command line: ".cmake"`。

**原因**：我**手写了工具链文件名，而且猜错了**。真实文件是 `cmake\gcc-arm-none-eabi.cmake`。

**正确做法**：**不要手写工具链路径**，直接用 CubeMX 生成的预设：
```powershell
cmake --preset Debug
cmake --build --preset Debug
```

**记住一句话**：**CubeMX 每次生成工程都会送你一份 `CMakePresets.json`（参数预设表）**，里面已经写好"用 Ninja、用哪个工具链文件、产物放哪"。手写 = 自找麻烦（这叫"先找轮子，别自己造"）。

## A3. `CMake was unable to find a build program corresponding to "Ninja"`

**现象**：配置阶段报找不到 Ninja，但 ninja 明明装了。

**原因**：ninja 的目录**不在那个终端进程看到的 PATH 里**。

**关于 PATH 的关键认知**（这条最容易绕晕）：
- **已保存的 PATH ≠ 当前进程看到的 PATH**。进程在**启动那一刻**把 PATH"拍了个快照"，之后再改系统 PATH，**它看不到**；
- 从**资源管理器**启动的终端，继承的是**资源管理器手里那本旧手册**（explorer 可能已经跑了好几个小时）；
- 用 **`setx` 或直接改注册表**的方式加 PATH，Windows **不会广播"环境变量变了"的通知**（用"系统属性 → 环境变量"对话框改才会广播）。

**正确做法**（按彻底程度）：
1. 注销 / 重新登录（最彻底）；
2. 任务管理器 → 重启「Windows 资源管理器」；
3. 当前窗口临时补一句 `$env:Path += ";D:\ForDownload\stm32-env\ninja"`（我们实际用的，永远管用）；
4. 长期省事：用 `tools\build.ps1`（它自己补 PATH）。

**记住一句话**：**排查时不要相信"我以为它是这样"，要去读它实际的值**（`$env:Path` vs `[Environment]::GetEnvironmentVariable('Path','User')`）。

## A4. 控制台中文乱码（`姝ｅ鸡鐩爣鍙戠敓鍣?`）

**现象**：裁判脚本自己打印的中文正常，**C++ 测试程序打印的中文全是乱码**。

**原因**：**编码对不上**。
- C++ 程序把中文按 **UTF-8** 吐出字节流；
- 你的控制台是 **GBK**，按 GBK 去解码 → 乱码；
- 而 `.ps1` 脚本存的是 **UTF-8 with BOM**，那个 **BOM 是"我是 UTF-8"的暗号**，PowerShell 认得，所以脚本的中文是对的。**C++ 输出的字节流没有暗号**，控制台只能猜。

**正确做法**：**命令行工具的输出一律用纯 ASCII（英文）**；中文写在 `.md` 文档里，用 VS Code 看。所以裁判和测试程序的输出全是英文。

**记住一句话**：**乱码不代表文件坏了，是"谁按什么编码读"的问题。**

## A5. 工程构建完成后要认识的两个数字

```
[34/34] Linking C executable C_project.elf
FLASH: 28748 B / 1 MB (2.74%)     RAM: 2584 B / 128 KB (1.97%)
```

- **记住这个基线**（约 28 KB Flash / 2.5 KB RAM）。以后每加一段代码就重编一次看体积变化——**突然涨很多 = 你引入了大东西**（比如浮点 `printf` 会一次加约 10 KB）；
- `.elf` 文件 1204 KB 但 Flash 只占 28.7 KB：**大部分是调试信息**（给调试器看的），真正烧进芯片的只有 28.7 KB；
- `ninja: no work to do.` = **增量构建**：只重编改动过的文件，所以每次构建只要几秒。

# 二、B1 阶段（正弦目标发生器 `SineRef`）

## B1-1. `error: invalid use of 'void'`（我写了 `(void)amplitude=1;`）

**原因**：两处错。
1. `(void)amplitude` 是一个**表达式**（意思是"把这个值丢掉"，原本是"我故意不用这个参数"的标记），**它不是变量，不能放在 `=` 左边**——相当于想把数字放进"空气"里；
2. 更糟的是右边写了 `=1`：那是**写死的常数**，外面传 2 或 5 都没用，参数白传了。

**正确做法**：
```cpp
amplitude_ = amplitude;   // 把外面递进来的值，抄进这个对象的"长期记忆"
```

**记住一句话**：**`(void)x;` 是"我故意不用它"的占位符，不是赋值目标**——要实现功能时把它删掉。

---

## B1-2. `error: 't' was not declared in this scope`（我写了 `t=ticks_*0.001;`）

**原因**：**C++ 要求先声明变量的类型**，再使用。没告诉编译器"`t` 是什么盒子"，它就不认识这个名字。

**正确做法**：
```cpp
const float t = ticks_ * kSampleTime;   // 声明 + 初始化一步到位
```

**记住一句话**：报错说「**was not declared**」= 十有八九**忘了声明变量**（或拼错了名字）。

---

## B1-3. 测试说「250 拍应该 +1」，我却算出 `0.24740`——**漏了 `2π`**

**怎么定位的（这个方法比结论重要）**：把 4 个失败值排开看：

| 测试说的时刻 | 我算出的值 | 这等于 |
|---|---|---|
| t = 0.25 s | 0.24740 | `sin(0.25)` |
| t = 0.50 s | 0.47943 | `sin(0.50)` |
| t = 0.75 s | 0.68164 | `sin(0.75)` |
| t = 1.00 s | 0.84147 | `sin(1.00)` |

→ 我喂给 `sin()` 的角度是 **0.25 弧度**，正确答案该是 **π/2 ≈ 1.5708**；比值 `1.5708 / 0.25 = 6.2832 = 2π` ✅ 一眼定位。

**原因**：`sin()` 要的是**弧度**，而 `f × t` 的单位是**圈数**。
```
freq_hz_ * t  单位 = (圈/秒) × 秒 = 圈数
1 圈 = 360° = 2π 弧度
→ 弧度 = 2π × f × t + φ
```

**正确做法**：`sinf(kTwoPi * freq_hz_ * t + phase_rad_)`

**两个"假绿"的教训**：当时 `phase pi/2` 那条测试**绿了**——因为 `sin(0 + π/2) = 1` 恰好对，把缺失的 `2π` 掩盖了。所以：
> **"绿了几条"不能代替"看数值"。**

**记住一句话**：**写公式前先检查单位**（量纲分析）——能挡掉一半的数学 bug，也是答辩爱问的点。

---

## B1-4. `ticks_ = 0.0f;` —— 整数变量收到浮点字面量

**现象**：编译通过，测试也过（因为 `0.0f` 恰好等于 `0`），**但是隐患**。

**原因**：`ticks_` 是 `uint32_t`（整数），右边是 `float`（小数）。编译器**默默帮你转换**：
```cpp
ticks_ = 1.9f;   // 你以为是 1.9 → 实际存进去的是 1（小数被砍掉）
ticks_ = 3.7f;   // 实际是 3
```

**正确做法**：**整数就用整数写**：`ticks_ = 0;`

**记住一句话**：这种"编译器帮你转、但转的不是你想的"叫**隐式类型转换**，是 C/C++ 最经典的 bug 来源——**在嵌入式里尤其致命**（角度算错一位，轴就转飞）。

---

## B1-5. 代码能跑 ≠ 代码合格（风格评审 5 条）

| 我写的 | 应该写成 | 为什么 |
|---|---|---|
| `ticks_=0.0f;` | `ticks_ = 0;` | 类型错配（见 B1-4） |
| `ticks_=ticks_+1;` | `++ticks_;` | 惯用法，"数一下"的标准写法 |
| `float t=0.0f;`<br>`t=ticks_*kSampleTime;` | `const float t = ticks_ * kSampleTime;` | 一步到位；`const` 表明"算完不该再改"；避免忘初始化 |
| `amplitude_=amplitude;`<br>`kTwoPi*freq_hz_* t` | `amplitude_ = amplitude;`<br>`kTwoPi * freq_hz_ * t` | **运算符两边要空格**（队里风格指南有要求，评审会看） |
| 留着 `// TODO(B1-1)` | 删掉，或改成说明性注释 | 做完还挂 TODO，别人以为你没做完 |

> 一句话：**代码是写给人读的**。队友、评委、未来的你都要读它。同一个代码库风格一致 = 专业度。

## B2-2. 公式背对了，还是可能踩这两个坑

### 坑① `last_err_ = err;` 放错位置 → 微分项恒为 0

- `last_err_` = **上一拍的误差**。算微分时必须用**旧值**：`deriv = err - last_err_`
- 若在算 `deriv` **之前**更新它 → `deriv = err - err = 0`，**D 项完全失效**（电机更爱振荡）
- 若真的写在函数**最开头** → 直接编译不过（`err` 还没声明，跟 B1-2 是同一个坑）
- 两个基础事实：**`err` 是局部变量、不跨调用存活**；赋值是"**抄数字**"不是"建立链接"，抄完再改 `err` 不影响 `last_err_`

> **通用纪律：先用旧记忆算，最后再更新记忆。**（像称体重：先算"今天−昨天"，再把今天抄进"昨天"那一栏）

### 坑② 饱和时还在攒积分 → 积分饱和（integral windup）

- 输出已被限幅夹住时，再累加的积分**换不来任何输出**，纯粹变成"有害负债"
- 后果：误差反向后要先把虚账还完 → **该刹车时刹不住**（滞后、过冲、堵转解除后猛冲）
- 做法：超限时 `integ_ -= err`（**只撤本拍，不清零**——负载还在，真实需求不能抹掉）

# 三、概念速查（答辩口径）

## `#include "SineRef.h"` 到底干了什么？
**在编译前，把这个头文件的全部内容原样"粘贴"到这一行的位置。** 所以 `kSampleTime` 和 `class SineRef` 就真的出现在 `.cpp` 里了 → 你能调用它。

| | 类比 |
|---|---|
| `.h` 头文件 | **菜单**（有什么菜、长什么样） |
| `.cpp` 实现 | **后厨**（真正做菜） |
| `#include` | 后厨说"**把菜单拿来**" |

为什么放头文件？**多个文件都要用**（`SineRef.cpp`、`test_core.cpp`、以后的 `ControlTask.cpp`）→ 一处定义，人人可见。

> 附带观察：在 `test_core.cpp` 里要写 `rm::kTwoPi`（带前缀），因为它写在 `namespace rm` **外面**；在 `SineRef.cpp` 里直接写 `kTwoPi` 就行，因为它在 `namespace rm` **里面**。

## `const` / `constexpr`
- **`const` = 只读**：这个盒子封起来了，只准看，不准改；一改编译器立刻拦。
- **`constexpr` = 编译期常量**：编译的时候就算好了，更"硬"（我们的 `kSampleTime` 用它）。
- 成员函数后面的 `const`（如 `float value() const`）= **承诺"我不改对象内部的数据"**；`step()` 要改 `ticks_`，所以**不能**加 `const`。
- 价值：① 让编译器当第一道审查员（防手滑）② 表达意图 ③ 便于优化（`const` 数组可放 Flash 省 RAM）。

## `float` vs `double`（为什么浮点字面量都带 `f`）
| 写法 | 大小 | 在 Cortex-M4 上 |
|---|---|---|
| `0.0f` | 32 位 float | **FPU 硬件加速** ⚡ |
| `0.0` | 64 位 double | **软件模拟，慢几十倍** 🐢 |

- **`f` 后缀 = "这是个 float 字面量"**。不写就是 double；
- 运算里混进一个 double，**整个表达式都会升级成 double**；
- 后果：1 kHz 的中断里用 double，等于每个周期多做几千条指令，**可能在下一次中断到来前跑不完**（中断必须在 1 ms 预算内跑完）；
- `float t = 0.0;` 还是"大箱子塞小箱子"的隐式窄化转换，严格模式会警告。
- 规矩：**浮点字面量一律带 `f`**。

## 为什么时间用「整数计数」，不用浮点累加 `t += 0.001f`？
1. **`0.001f` 在二进制里根本不精确**（是个无限循环小数），存进去就被截断了。累加是"**每加一次都舍入一次**"，误差会**随时间积累（漂移）**——刚开始看不出来，跑久了曲线就跑偏；
2. **整数计数是精确的**：数到 1000 就是正好 1 秒；`reset()` 一句话回到起点；
3. 附带好处：整数运算比浮点快，也不会因为"大数吃小数"丢精度。
4. （进阶）跑几小时时，`float t` 本身的分辨率也会变差（t≈3600 s 时 float 的间隔约 0.2 ms，已经和 1 ms 的节拍同量级）。更专业的做法是**用相位累加器**或**对 `ticks_` 取模**，让时间只在 `[0, T)` 内取值。

## 为什么控制周期是 1 kHz？
周期越短反应越快，但**越吃 CPU**；1 kHz（每 1 ms 一次）是机器人电控的常用节拍。我们工程里 TIM6 就按 1 kHz 配的，所以 `kSampleTime = 0.001f` 不是随便定的，是**照硬件配置抄下来的**。

| `'t' was not declared` | 「没声明变量就对它进行运算」 | ✅ 对。完整说法：C++ 要求**先声明类型再使用**。 |

## B2 · PID 控制器

| 题目 | 我的回答 | 订正 |
|---|---|---|
| P、I、D 各自在干什么 | P「计算误差的占比，差距越大，调整速度越快」；I「计算误差在时间上的累积，累积多了就更快调整」；D「做微分减少调整速度过快导致震荡」 | **方向对，但漏了最关键的一条**：I 的真正使命是**消除静差**（只用 P，实际值会永远差一点点、到不了目标）。用词也要改准：「占比」应说"**与误差成正比**"；D 的准确说法是"看**误差的变化率**，起**阻尼**和**提前刹车**作用，抑制超调与振荡"。 |
| 为什么积分 ×T、微分 ÷T | 「积分是误差在时间上的累加，微分是某一单位时刻的变化速率」 | **描述了"是什么"，没回答"为什么"**。答案是**单位换算**：`Σe` 的单位是"误差 × 次数"，×T（秒/次）才变成"误差 × 秒"（真正的时间积分）；`(e−e₁)` 是"两拍之差"，÷T 才变成"误差 ÷ 秒"（变化率）。 |
| 不限幅 / 不回退会怎样 | 「不限幅：突变过快危险，尤其刚通电时」；「不回退：超出上限后仍然累加，障碍消除后会用力过猛」 | **两条都对** ✅ 补一个现象描述：不回退的典型症状是"**该刹车时刹不住**"——误差已经反向，输出却还被顶在限幅上（得先把虚账还完）。 |

# 五、要沉淀成习惯的工程原则

1. **先复现，再动手**：改代码前先跑一次看现状（红/绿），别蒙着眼改。
2. **用证据定位根因，不猜**：`0.2474 = sin(0.25)`、`比值 = 2π`——数值会说话。
3. **学会读报错**：`文件 : 行号 : 列号 : 类型 : 说明`，编译器还会把出错的行抄给你、用 `^` 指到列。
4. **编译报错是朋友**：它精确到行列；"编译过了但结果不对"才难查。
5. **绿了不等于对了**：注意**假绿**（碰巧相等的情况），关键测试要**看数值**。
6. **写公式先查单位**（量纲分析）。
7. **能跑 ≠ 合格**：风格、命名、注释、`const` 正确性都算代码质量。
8. **别手写本该由工具提供的东西**（工具链路径、预设参数）——先找轮子。
9. **怀疑"我以为"**：去读实际值（PATH、寄存器、变量）。
