## 0. 先建立三个心智模型

### 0.1 类（class）= 一台打包机的图纸

```cpp
rm::FloatFrame f;      // 这一行在"造一台机器"
f.reset();             // 按"清零"按钮
f.push(1.0f);          // 按"塞一个数"按钮
```

| 类里的东西 | 类比 | 术语 |
|---|---|---|
| `buf_`、`count_` | 机器内部零件 | **成员变量**（member variable） |
| `reset()`、`push()` | 机器外壳上的按钮 | **成员函数**（member function）/ 方法 |
| `private:` 下面的 | 拧开外壳才能碰的零件 | **私有**：只有类自己能用 |
| `public:` 下面的 | 外壳上的按钮 | **公开**：外面可以按 |

**为什么要把"数据"和"操作数据的函数"打包成一台机器？** 三个实在的理由：

1. **保护数据**：如果 `count_` 谁都能改，别人写个 `count_ = 100`，`size()` 就变成 404 字节，
   可料仓只有 64 字节 → **越界读**（读到别的内存、发出垃圾甚至崩）。封起来就改不了。
2. **只暴露按钮，不暴露齿轮**：上机时只需要知道"按 push 就塞进一个数"，
   不需要知道里面字节怎么摆。
3. **维护"不变量"**：协议要求"帧尾永远紧跟在数据后面"，
   这种规矩**只有机器自己才守得住**（每次 `push` 都顺手补帧尾）。靠外面的人自觉必然出错。

### 0.2 声明与定义 = 菜单与厨房

| | 写在哪 | 内容 | 类比 |
|---|---|---|---|
| **声明**（declaration） | `.h` | 只说"有这么个函数，叫什么、收什么、还什么" | **菜单**：菜名、价格 |
| **定义**（definition） | `.cpp` | 真正的函数体（怎么算） | **厨房**：怎么做 |

为什么非要拆成两份：

1. 别人（判题器、别的模块）只要看菜单就能编译，**不需要看厨房**；
2. 改厨房（改实现）**不用动菜单**，别人也不用重新编译 —— 大工程里省大量编译时间；
3. **判题器只能靠菜单知道你承诺了什么** → 所以头文件是"合同"。
   这也是为什么规则是"只填 TODO，不要改 `.h`"：改合同等于换题目。

### 0.3 `const` = 承诺

在这份代码里 `const` 出现三次，含义各不同：

| 出现位置 | 含义 | 类比 |
|---|---|---|
| `constexpr uint16_t kCapacity` | 编译期就定死的常量 | 图纸上标好的尺寸 |
| `uint16_t count() const` | 这个函数**承诺不修改对象内部数据** | "读数按钮"，读数不该改变机器状态 |
| `const uint8_t* data()` | 返回的指针指向**不许改**的字节 | 只给你看，不给你改 |

## 1. `FloatFrame.h` 逐行拆解

### 1.1 开头四行

```cpp
#pragma once            // ①
#include <cstdint>      // ②
namespace rm {          // ③
class FloatFrame {      // ④
```

**① `#pragma once` —— "这个文件只让编译器看一遍"**

头文件会被**很多个** `.cpp` 用 `#include` 展开。如果不设防，同一个类被定义两次 →
编译器报"重复定义"。这一行就是"防重复展开"的开关。
（作业 `Tasks.h` 里用的是等价写法：`#ifndef TASKS_H / #define / #endif`。）

**② `#include <cstdint>` —— 借来 `uint8_t` 这些名字**

这些叫**定宽整数类型**，是嵌入式里的标配：

| 类型 | 位数 | 取值范围 | 为什么不用 `int`/`char` |
|---|---|---|---|
| `uint8_t` | 恰好 8 位 | 0 ~ 255 | 正好一个字节。串口就是按字节发的，必须精确 |
| `uint16_t` | 恰好 16 位 | 0 ~ 65535 | 索引用 |
| `uint32_t` | 恰好 32 位 | 0 ~ 4294967295 | 时间戳、浮点位模式 |

`int` 在有的平台是 2 字节、有的 4 字节 —— **协议是按字节定义的，位数不精确就要出 bug**。
`u` = unsigned（无符号，只有 0 和正数），`_t` = type（类型的命名后缀）。

**③ `namespace rm { ... }` —— 给名字加"姓氏"**

- `rm` = RoboMaster。作用是**防止撞名**：别的库里也有叫 `FloatFrame` 也不怕，
  因为我们这个全名叫 `rm::FloatFrame`。
- `::` 读作"作用域解析运算符"，就是"归属"：`rm::FloatFrame` = "rm 家的 FloatFrame"。
- ⚠️ 头文件开了 `namespace rm {`，**`.cpp` 里也必须开同一个**。
  不开，编译器就认为你定义的是"别人家的 FloatFrame"，和声明对不上 → 编译/链接报错。
  **这是新手高频坑。**

**④ `class FloatFrame {` … 结尾的 `};`**

⚠️ **结尾那个分号不能漏**。类定义本身是一条语句；漏了分号，编译器会报一堆
莫名其妙的错，而且错误位置常常指向下一行。

### 1.2 访问权限

```cpp
 public:              // 外壳上的按钮，外面能用
  void reset();
  ...
 private:             // 内部零件，只有自己能用
  uint8_t  buf_[kCapacity] = {};
  uint16_t count_          = 0;
```

- `class` 默认是**私有**的；`struct` 默认是公开的（两者只差这一点）。
- 判题器里那句 `rm::FloatFrame::kMaxFloats` 不加对象名也能用，
  是因为它是 `static`（属于类本身，不属于某个具体对象）。

### 1.3 四个按钮的声明

```cpp
  void reset();                    // 声明
  bool push(float v);              // 声明
  uint16_t count() const;          // 声明（注意末尾的 const）
  const uint8_t* data() const;     // 声明（注意末尾的 const）
```

**`void reset();`**

- `void` = 不返回任何东西（这个按钮只干活，不给你回话）。
- `()` 里空的 = 不收参数。

**`bool push(float v);`**

- `bool` = 返回"真/假"，用来报告**成功还是失败**。这叫"用返回值报错"，
  比打印一行字或直接崩掉专业得多。
- `float v` = 收一个浮点数。注意这是**值传递**：把外面的数**拷一份**进来，
  机器内部怎么动都影响不到外面。

**`uint16_t count() const;`** ← 末尾那个 `const` 是关键

它是"**const 成员函数**"，意思是：**这个函数承诺不修改机器内部的数据。**

- 通俗：这是**读数按钮**（看还有几个数），读数不该改变机器状态 → 标 `const`。
- 为什么"必须"标：调用方手里常常是一个**不许改的对象**（`const FloatFrame&`）。
  C++ 规定：`const` 对象**只能调用标了 `const` 的函数**。不标，判题器就编不过。
- 它还帮你**自查**：如果哪天你在 `count()` 里手滑写了 `count_ = 0;`，
  编译器当场报错拦住你。

**`const uint8_t* data() const;`** ← 这行要拆开读

**读法**：从右往左 —— "函数是 `const` 的（不改自己）→ 返回一个指针 →
指针指向 `const uint8_t`（不许改的字节）"。

- **为什么返回指针，而不是把 64 字节数据全拷出来？**
  串口发送函数要的就是"**地址 + 长度**"两样东西 ——
  给它一个门牌号，比搬一整车货快得多。
- **为什么加 `const`？** 外面只需要**读**这些字节去发串口，**绝不允许改**。
  用类型把"只读"写明，对方想改都编译不过 —— 这叫**用类型表达意图**。

### 1.4 两个零件 + 命名习惯

```cpp
  uint8_t  buf_[kCapacity] = {};
  uint16_t count_          = 0;
```

- **尾部的下划线**（`buf_`、`count_`）：**成员变量**的命名习惯，
  一眼和局部变量、参数区分开。（不是语法要求，是团队约定。）
- **`k` 开头**（`kCapacity`）：**常量**的命名习惯（`k` = konst）。
- **`= {}`**：**默认成员初始化**，把整个数组**填 0**。
  不写的话，刚造出来的对象里料仓装的是**上电残留的随机字节** ——
  万一里面恰好有帧尾模式 `00 00 80 7F`，你还没 push 任何数据，
  上位机就已经切出一帧垃圾了。
- **`= 0`**：`count_` 从 0 开始（表示"一个数都没塞"）。

> 这套写法体现一个原则：**对象一造出来就是合法可用的状态**，
> 不需要用户记得先调一次"初始化"。少一个可以忘记的步骤，就少一类 bug。

## 2. `FloatFrame.cpp` 逐行拆解

```cpp
#include "FloatFrame.h"     // ①
#include <cstring>          // ②

namespace rm {              // ③

void FloatFrame::reset() {  // ④
}

bool FloatFrame::push(float v) {
  (void)v;                  // ⑤
  return false;             // ⑥
}
```

**① `#include "FloatFrame.h"` —— 为什么 `.cpp` 第一件事是包含自己的头？**

为了让编译器**拿菜单对厨房**：如果你把 `push` 的返回类型写成 `int`（菜单写 `bool`），
编译器立刻报错。**这是免费的自我检查**，别省。

**② `#include <cstring>`** —— `memcpy` 的名字住在这里（`std::memcpy`）。

**③ `namespace rm {`** —— 必须和头文件一致（见 1.1 ③）。

**④ `void FloatFrame::reset()`** —— `FloatFrame::` 是"**归属说明**"：
告诉编译器"这是 FloatFrame 那台机器的 reset 按钮的实现"。
类外定义成员函数必须带这个前缀。

**⑤ `(void)v;`** —— 骨架里留的**占位符**：意思是"我知道有个参数 `v`，
现在故意不用它"，用来避免编译器警告"定义了却没用的参数"。**实现时删掉这行。**

**⑥ `return false;`** —— 临时的返回值，让骨架能编过（所以判题器里现在一堆红项）。
实现时替换成真逻辑。

## 3. 底层机制：对象在内存里到底是什么

这一章理解了，"每句话在干什么"就彻底通了。

### 3.1 一个对象就是一段连续的内存

```cpp
rm::FloatFrame f;    // 在栈上占 sizeof(rm::FloatFrame) = 66 字节
```

| 内存偏移 | 内容 | 类型 |
|---|---|---|
| 0 ~ 63 | `buf_`（料仓） | 64 个 `uint8_t` |
| 64 ~ 65 | `count_`（计数器） | 1 个 `uint16_t`（2 字节） |

总共 **66 字节**（没有多余填充：64 是偶数，`uint16_t` 要求的 2 字节对齐刚好满足）。

> **为什么 `uint16_t` 要求"2 字节对齐"？** CPU 读 2 字节时更希望地址是偶数。
> 这也是"未对齐访问"问题的来源 —— 某些 CPU 架构访问未对齐地址会**直接硬件异常**。

### 3.2 成员函数**不占对象空间**，而且有隐藏参数 `this`

机器有一百台，但"按钮说明书"只有一份。

```cpp
f.push(1.0f);
```

编译器其实把它变成了：

```cpp
FloatFrame::push(&f, 1.0f);      // 多传了一个"我是哪台机器"的地址
```

那个隐藏的 `&f` 就是 **`this` 指针**。由此可以推出两件事：

- 你在 `push` 里直接写 `count_`，编译器自动补成 `this->count_`
  （"**我这台机器的** count_"）→ 所以同一个函数能服务所有对象。
- 在 `const` 成员函数（`count()`）里，`this` 的类型变成 `const FloatFrame*` →
  于是你在里面写 `count_ = 0;` **编译期就被拦住**。
  这就是 0.3 里"承诺不改自己"的底层实现方式。

### 3.3 为什么"封装"才有真实价值

因为**不变量只有放在一起才守得住**：

```
不变量：size() 永远等于 count()*4 + 4，且帧尾永远紧跟在数据后面
```

- 如果 `buf_`、`count_` 是散着的全局变量，谁都能破坏这个规矩；
- 封进类里、由 `push` 一个人负责维护它 → 规矩永远成立。

**这就是"封装"的价值，不是"看起来高级"。**

### 3.4 栈上的对象：用完就没

```cpp
{
  rm::FloatFrame f;     // 造出来（占 66 字节栈空间）
  f.reset();
  f.push(1.0f);
}                        // 出了这个大括号，f 自动消失，内存还给栈
```

不需要手动"销毁"，这就是 C++ 对象比手写 `malloc/free` 省心的地方。
判题器里每个测试块 `{ ... }` 都造一台新机器，彼此绝不干扰。

## 4. 两个基础工具

### 4.1 `constexpr` —— "编译期就算好的常量"

**一句话**：在"编译的时候"就已经确定、并写死在程序里的数字。运行时不需要再算它。

**类比**：装修**图纸上标好的尺寸**（"客厅宽 3.6 米"），工人施工时不用再量。

| 写法 | 谁保证它不变 | 什么时候知道值 | 有类型吗 |
|---|---|---|---|
| `#define kCap 64` | 没人管（纯文字替换） | 写代码时 | ❌ 没有类型，就是个文本 |
| `const uint16_t kCap = 64;` | 编译器 | 可能是运行时才知道 | ✅ 有 |
| **`constexpr uint16_t kCap = 64;`** | 编译器 | **编译时一定知道** | ✅ 有 |

**为什么 `#define` 不好**：它只是文字替换，编译器不认识它，出错时报错信息莫名其妙。
现代 C++ 一律用 `constexpr` 代替。

在本关代码里：

```cpp
static constexpr uint16_t kCapacity = 64;                            // 缓冲区 64 字节
static constexpr uint16_t kTailSize = 4;                             // 帧尾 4 字节
static constexpr uint16_t kMaxFloats = (kCapacity - kTailSize) / 4;  // 编译期就算出 15
```

- **`static`（在类里面）** = "这一份属于**类本身**，不属于某个具体对象"，
  所以不创建对象也能用：`rm::FloatFrame::kMaxFloats`（是 `::`，不是 `.`）。
- **为什么 `(64-4)/4` 能当 `constexpr`**：输入都是编译期常量 → 编译器当场算出 15 并写死。

**为什么这里必须用它**：

```cpp
uint8_t  buf_[kCapacity] = {};
```

**数组长度必须是编译期常量** —— 编译器在编译时就得知道"要给这个数组留多少字节"
（必须先定好柜子多宽，木工才能下料）。

**额外好处**：`constexpr` 的数字**不占 RAM**，也没有运行时开销。
嵌入式 RAM 只有 20 KB，每个字节都要省。

### 4.2 `memcpy` —— "按字节搬运工"

**一句话**：从一块内存搬 N 个字节到另一块内存。**它不看内容，只数字节。**

**类比**：搬家工人。"从 A 屋搬 **4 个箱子** 到 B 屋" ——
他不打开箱子看里面是什么，只知道"搬 4 个，原样搬过去"。

```cpp
void* memcpy(void* dst, const void* src, size_t n);
        // 目的地      源头（只读）    搬几个字节
```

- **`void*`** = "什么类型都行"的指针（因为它不关心你搬的是 float 还是 int）
- **`const void* src`** = 源头加 `const`，表示"我保证不改你"
- **`size_t`** = "字节数"这种整数类型（`sizeof` 得到的就是它）
- 头文件：`#include <cstring>`，调用写 `std::memcpy`

**为什么取 float 的位必须用它（关键区别）**：

| 写法 | 干了什么 | 结果 |
|---|---|---|
| `(uint32_t)3.14159f` | **数值转换**：把"三点一四"变成整数 | `3` ❌ |
| `std::memcpy(&bits, &v, 4)` | **位模式搬运**：把同样的 4 个字节原样搬过去 | `0x40490FD0` ✅ |

你要的是"这段二进制长什么样"，**不是**"这个数约等于几" → 所以要搬运，不要转换。

通用写法（这是 C/C++ 的固定套路，叫 type punning）：

```cpp
float    v    = 1.0f;
uint32_t bits = 0;
std::memcpy(&bits, &v, sizeof(bits));   // 4 字节原样搬过去
// 现在 bits == 0x3F800000  ← 1.0f 的真实位模式
```

- **`&v`** = "v 所在的那块内存的地址"（`&` 取地址）
- **`sizeof(bits)`** = "bits 占几字节"（编译期算出来 = 4）
- 反向同理：`std::memcpy(&v, &bits, 4)` 把位模式还原成 float

**为什么不能图省事写 `*(uint32_t*)&v`？** 两个雷：

1. **严格别名规则（strict aliasing）**：编译器优化时会**假设**
   "uint32_t 的指针不会指向 float 那块内存"。你违反了它的假设，
   它就可能把这段代码优化掉或优化错 —— 而且往往在开了 `-O2` 之后才炸，最难查。
2. **地址未对齐（unaligned access）**：某些架构访问未对齐地址会**直接硬件异常**。

→ **标准规定：取位模式就用 `memcpy`。** 这是写嵌入式代码要天天守的规矩。

**会不会因为"函数调用"变慢？** 不会。4 字节这种固定长度的 `memcpy`，
GCC/Clang 会**直接编译成一条数据移动指令**，等于零开销。

> 小注解：`memcpy` 不管"两块内存重叠"的情况（重叠要用 `memmove`）。
> 这里源和目标互不相干，用 `memcpy` 就对了。

## 5. 命名约定速查表

| 写法 | 含义 | 例子 |
|---|---|---|
| `kXxx` | 常量 | `kCapacity`、`kMaxFloats` |
| `xxx_` | 成员变量 | `buf_`、`count_` |
| `Xxx()` | 函数/方法 | `reset()`、`push()` |
| `Xxx` | 类名/类型名 | `FloatFrame` |
| `m_name` / `name_` | 成员变量（不同团队习惯不同，本仓库用 `name_`） | —— |

**这些不是语法要求，是团队约定** —— 大工程里能一眼分辨"这是什么"，能救命。

## 6. 读这类代码的三个通用技巧

1. **声明从右往左读**
   `const uint8_t* data() const` → "函数 `const` → 返回指针 → 指向 `const` 的 `uint8_t`"。
2. **先看 `.h` 再看 `.cpp`**
   `.h` 告诉你"这台机器能干什么"（菜单），`.cpp` 才告诉你"怎么干"（厨房）。
   看不懂 `.cpp` 时，先回去读 `.h`。
3. **把类当机器**
   `private` 是内部零件，`public` 是外壳按钮，`static` 是贴在铭牌上的参数。
